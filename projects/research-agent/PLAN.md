# 리서치 에이전트 — 기획서

> DeepLearning.AI *Agentic AI* 모듈 1의 실습 과제를 자체 구현으로 대체하는 프로젝트.
> 작성일 2026-08-03

## 1. 배경

강의의 "Try the research agent"(Code Example, 1h)는 Pro 전용이며, 모듈 2의 ungraded 랩도
동일하게 잠긴 것을 확인했다. **무료 티어에서는 랩 환경 전체를 이용할 수 없다.**

가진 것은 세 가지다.

| 자원 | 내용 |
|---|---|
| 강의 영상 (무료) | 개념 — [모듈 1 학습 정리](../../notes/module-1-agentic-workflows/README.md) |
| 랩 제목 | 무엇을 만들어야 하는지에 대한 명세 |
| [공식 저장소](https://github.com/https-deeplearning-ai/agentic-ai-public) | 참조 구현 (라이선스 없음, 학습 참조용) |

없는 것은 **정답 코드가 아니라 채점**이다. 따라서 채점을 자체 eval로 대체하는 것이
이 프로젝트의 부수 목표가 된다.

## 2. 목표

**모듈 1 레슨 1에서 설명된 리서치 에이전트를 동작하는 형태로 완성한다.**

원문의 프로세스 정의 ([01번 노트 §4](../../notes/module-1-agentic-workflows/01-what-is-agentic-ai.md)):

> 리서치 계획 수립 → 웹 검색 엔진 호출 및 페이지 다운로드 → 결과 종합·순위화
> → 아웃라인 작성 → "편집자" 에이전트가 일관성 검토 → 종합 마크다운 리포트 생성

이 문장이 곧 요구사항 명세다. 이 순서를 그대로 구현한다.

### 완료 기준

| # | 기준 | 검증 방법 | 결과 |
|---|---|---|---|
| 1 | 주제 하나를 입력하면 마크다운 리포트가 생성된다 | `python run.py "주제"` 실행 | ✅ 1,096 단어 |
| 2 | 리포트에 인라인 인용과 References 섹션이 있다 | eval 자동 판정 | ✅ |
| 3 | 인용된 URL이 전부 실제 수집된 소스에 존재한다 | eval 자동 판정 (환각 검출) | ✅ **21/21** |
| 4 | 각 단계의 중간 출력이 트레이스로 남는다 | `traces/*.json` 확인 | ✅ 7단계 |
| 5 | 반성(critique → revise) 단계가 실제로 초안을 바꾼다 | 초안/최종본 diff | ✅ 18.6% 변경 |

3번이 이 프로젝트의 핵심 지표다. 나머지는 형식 요건이다.

## 3. 범위

### 포함

- 7단계 워크플로우 (계획 → 조사 → 종합 → 아웃라인 → 초안 → 비평 → 수정)
- **직접 구현한 도구 호출 루프** (docstring → JSON Schema → tool_call → 실행 → 되먹임)
- 도구 3종: Tavily 웹 검색, Wikipedia, arXiv
- 단계별 트레이스 기록
- 객관적 eval 스크립트
- CLI

### 제외 (그리고 그 이유)

| 제외 항목 | 이유 |
|---|---|
| FastAPI · Postgres · Docker | 공식 저장소엔 있으나 에이전틱 로직과 무관한 인프라. 학습 초점을 흐린다 |
| PDF 본문 추출 | `pdfminer.six`/`pymupdf`가 코스 requirements에 없음. arXiv 초록으로 충분 |
| 프레임워크 (LangChain 등) | 강의의 "밑바닥부터 구현" 원칙. [CLAUDE.md](../../CLAUDE.md) 하드 제약 |
| 멀티 에이전트 협업 | 모듈 5 주제. 여기서 다루면 범위가 흐려진다 |

## 4. 설계 결정과 근거

| 결정 | 선택 | 근거 |
|---|---|---|
| LLM 제공자 | OpenAI (`gpt-4.1-mini`) | 보유 키. aisuite를 거치므로 교체는 문자열 변경 |
| 도구 호출 루프 | **직접 구현** | 모듈 3의 핵심 메커니즘. aisuite `max_turns`에 위임하면 배울 것이 사라진다 |
| 실행 형태 | 파이썬 모듈 + CLI | eval 반복 실행과 버전 관리에 유리 |
| 검색 백엔드 | Tavily + Wikipedia + arXiv | 강의와 동일한 구성. Tavily는 키 없으면 자동 제외 |
| Tavily 검색 깊이 | `basic` (1 크레딧/회) | 무료 1,000 크레딧 기준 1회 실행당 10 크레딧 미만 |

### aisuite를 쓰면서 루프를 직접 짜는 것이 가능한 근거

[`aisuite/client.py:234`](../../venv/lib/python3.12/site-packages/aisuite/client.py#L234)에서
자동 도구 실행은 `max_turns is not None and tools is not None`일 때만 발동한다.
`max_turns` 없이 스키마 dict를 넘기면 provider로 그대로 전달된다.
따라서 **모델 교체 가능성(aisuite)과 루프 직접 구현을 동시에** 가져갈 수 있다.

### 검색 백엔드 부재를 설계로 흡수하기

Tavily 키가 없는 것은 제약이지만, [03번 노트의 모듈성](../../notes/module-1-agentic-workflows/03-benefits.md)을
실습할 기회이기도 하다. 도구를 `RESEARCH_TOOLS` 리스트에 등록하는 구조로 만들어,
검색 엔진 추가가 **함수 하나 + 리스트 한 줄**로 끝나게 한다.

### 워크플로우 (7단계)

| # | 단계 | 담당 | 도구 |
|---|---|---|---|
| 1 | 리서치 계획 수립 | planner | — |
| 2 | 자료 수집 | researcher | **Wikipedia, arXiv** |
| 3 | 결과 종합·순위화 | analyst | — |
| 4 | 아웃라인 작성 | writer | — |
| 5 | 초안 작성 | writer | — |
| 6 | 비평 (무엇을 고쳐야 하는가) | editor | — |
| 7 | 수정 → 최종 리포트 | writer | — |

5~7단계가 [05번 노트의 5단계 워크플로우](../../notes/module-1-agentic-workflows/05-task-decomposition.md)에서
"에세이 작성"을 세 개로 쪼갠 그 부분이며, 동시에 반성(Reflection) 패턴이다.

**자율성 수준:** 단계 순서는 하드코딩, 2단계 안에서만 LLM이 도구를 선택한다.
[02번 노트](../../notes/module-1-agentic-workflows/02-degrees-of-autonomy.md)의 분류로는 **반자율적**.
플래너가 단계 순서까지 정하는 형태는 모듈 5의 주제이므로 여기서는 하지 않는다.

## 6. 평가 설계

모듈 1 레슨 6의 원칙: **미리 예측하지 말고, 만든 뒤 출력을 보고 eval을 만든다.**
따라서 아래는 *출발점*이며, 실제 출력을 본 뒤 항목이 추가될 것을 전제한다.

### 객관적 eval (코드로 판정)

| 지표 | 판정 | 왜 이 지표인가 |
|---|---|---|
| **인용 정합성** | 리포트에 등장한 URL ⊆ 수집된 소스 URL | **환각을 직접 검출.** 완전 객관적·이진적 |
| References 섹션 | 존재 여부 | 형식 요건 |
| 도구 사용 | 호출 > 0, 실패 0 | 모델이 자체 지식으로 답했는지 검출 |
| 링크 유효성 | 끊김(404/410) 0건 | 죽은 링크 검출 |
| 소스 다양성 | 서로 다른 도메인 수 | 한 출처에만 의존하는지 |
| 분량 | 단어 수 ≥ 400 | 최소 충실도 |
| 반성 효과 | 초안↔최종 유사도 < 98% | 반성 단계가 값을 하는지 |
| 가독성 | `textstat` Flesch (References 제외) | 강의가 `textstat`을 넣은 이유 |

> **1차 실행 후 수정된 항목** — 레슨 6의 "만든 뒤 고친다" 원칙대로 실제로 고쳤다.
> - 링크 유효성: `HEAD` 요청이 Wikipedia에서조차 403을 받아 멀쩡한 링크를 죽었다고 오판했다.
>   `GET` + 브라우저 User-Agent로 바꾸고, **차단(403/429)과 끊김(404/410)을 분리**했다.
> - 가독성: References 섹션의 긴 URL이 Flesch를 6점가량 깎아먹어 본문만 측정하도록 바꿨다.

**인용 정합성**이 대표 지표다. 강의가 예로 든 "경쟁사 언급 검출"과 같은 성격
— 코드로 셀 수 있고, 참/거짓이 명확하다.

### 하지 않을 것: LLM 판정자 단독 사용

레슨 6에서 강사가 1~5점 척도의 신뢰성 문제를 명시적으로 경고했다.
반성 단계 전후 비교 용도로만 참고하고, 합격/불합격 판정에는 쓰지 않는다.

## 7. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| **API 비용 누적** | 1회 실행 = LLM 호출 7~12회. 반복 실험 시 누적 | `gpt-4.1-mini` 사용, 검색 결과 캐싱, 개발 중 짧은 주제 사용 |
| Wikipedia 패키지 노후 | `wikipedia` 1.4.0은 2014년 이후 미유지보수. 최신 bs4와 충돌 가능 | 1순위 작업으로 동작 검증. 실패 시 `requests` + REST API 직접 호출 |
| 도구 미호출 | 모델이 도구를 안 쓰고 자체 지식으로 답변 | 트레이스에서 도구 호출 0건이면 eval 실패 처리 |
| arXiv 도메인 제약 | CS·물리·수학 등만 커버. 인문·의학 주제에서 빈손 | 도구 docstring에 명시, Wikipedia·웹 검색으로 보완 |
| Tavily 크레딧 소진 | 무료 월 1,000 크레딧. 반복 실험 시 소진 가능 | `basic` 깊이 사용(1크레딧), 개발 중 결과 캐싱 |

## 8. 비목표

- 프로덕션 품질의 에러 처리·재시도·레이트리밋
- 웹 UI
- 다국어 리포트 (영문 리포트 기준으로 만들고, 필요 시 한국어 옵션 추가)
- 공식 저장소 코드의 이식 — **직접 만드는 것이 목적이므로 완성 전에는 참조하지 않는다**

## 9. 완성 후 계획

1. 자체 eval 실행 → 결과 기록
2. 트레이스로 오류 분석 (모듈 4에서 배울 방식의 예습)
3. **그 다음에** 공식 저장소와 대조 → 무엇을 놓쳤는지 정리
4. 대조 결과를 `notes/`에 회고로 남김

3번을 완성 전에 하지 않는 것이 이 프로젝트의 학습 가치를 지키는 조건이다.
