| 항목 | 내용 |

## 이 랩이 특별한 이유

모듈 2의 두 랩은 **평가 방식이 정반대**입니다.

| | 04. 차트 생성 | 07. SQL 생성 |
|---|---|---|
| 출력 | 이미지 | SQL 쿼리 → 실행 결과 |
| 정답 | 없음 (주관적) | **있음 (객관적)** |
| 평가 | 멀티모달 LLM + 루브릭 | 정답 대조, 코드로 채점 |
| 외부 피드백 | 생성된 이미지 자체 | DB 실행 결과 / 에러 |

즉 [05번 노트](05-evaluating-reflection.md)의 **"객관적 평가 vs 주관적 평가"** 를 한 모듈 안에서 두 랩으로 나눠 보여주는 구성입니다.

## 직접 만든다면

SQL 쪽이 차트 랩보다 **재현하기 쉽습니다.** 멀티모달도, 이미지 채점도 필요 없기 때문입니다.

1. SQLite로 작은 판매 테이블 만들기 (product, color, quantity, sold_at)
2. 정답을 미리 아는 질문 10~15개를 손으로 작성 — **이게 실제 작업량의 대부분**
3. `generate → (reflect) → execute` 워크플로우
4. 두 조건으로 배치 실행 → 정답률 비교
5. 실행 에러를 검토 단계에 되먹여 [06번 노트](06-using-external-feedback.md)의 외부 피드백까지 적용

> 2번이 핵심입니다. 모듈 1의 리서치 에이전트에는 **정답 데이터셋이 없어서**
> "리플렉션 전/후 정답률" 같은 깔끔한 비교를 만들지 못했습니다.
> SQL은 정답이 존재하므로 그 비교가 가능해집니다.
